Editions

One brain on your machine,
or one for the team.

os-brain is the local brain of ns-brain, rewritten as open source with the same behaviour. It is for one person on their own machine. ns-brain's team edition adds a server, so one brain can be shared across machines and people. Both read the same storage format, so a brain moves between them.

os-brain

open source, MIT licence

  • Session hooks and recall on every prompt

  • The web UI inside the binary

Encryption at rest is missing from os-brain on purpose. One developer keeping their own data on their own machine has no second party to be protected from and full-disk encryption on the laptop is the right layer for that job. The file is readable only by its owner (mode 600) and stays out of git.

Moving a brain

Same format,
both ways.

The two editions write the same SQLite schema, so nothing is converted. A project's own brain/brain.db opens in either binary as it is. Memories, types, scopes, history and supersede links all come across.

A project kept in a shared store moves with export in one edition and import in the other, run in a project of the same name. Import keeps only the rows of the project it runs in:

$ ns-brain export --out ~/orchard.json --allow-outside  # in the ns-brain project
$ os-brain import ~/orchard.json --dry-run  # in the os-brain project of the same name
$ os-brain import ~/orchard.json --force

The export is every memory in cleartext, so it is refused inside the repository unless that path is gitignored: write it outside with --allow-outside. import --dry-run reports what would change and writes nothing. If the dump brings guardrails (the policy and constraint types), the import stops and asks for --force, because a guardrail binds every session of the project it lands in. Read them in the dry run first. Add --events to bring the activity log as well.

os-brain uses its own command name, its own OS_BRAIN_* variables and its own shared store at ~/.claude/os-brain/brain.db. It can sit beside an installed ns-brain without either one writing into the other's store.

Switching a project

From ns-brain
to os-brain.

Take ns-brain's hooks out first, then wire os-brain's. The uninstall keeps the database, so the memories are still there when os-brain opens it.

$ ns-brain uninstall          # read the plan
$ ns-brain uninstall --apply  # removes ns-brain's hooks, keeps brain.db
$ os-brain init               # wires os-brain's hooks to the same brain
$ os-brain wakeup             # check the brief shows your memories

Skip the uninstall and both editions' hooks stay wired: every session gets two briefs. The same holds the other way round.

A project that the team edition attached to its server cannot be switched this way, because its memories are not in any local file. os-brain refuses to run in a project whose brain.json names a team server or a zero-knowledge brain. It says which one, tells you to use ns-brain there and does not answer from an empty local file instead.

Export it from the team edition first, then import it into a local brain as above.
