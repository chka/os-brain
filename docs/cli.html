The six you use every day #

Learn these six and you know the tool. Everything after this section can wait until you need it.

$ os-brain brief                        # what this project believes. Read it first.
$ os-brain recall "nginx timeout"       # before you search files
$ os-brain remember "..." --body "..." --type gotcha
$ os-brain prefer "commit messages stay lowercase" --why "corrected twice"
$ os-brain log "deployed 1.4 to the edge box" --kind deploy
$ os-brain note billing-api "rounding moved to the ledger"  # never write into another project

Add --json to any command and you get structured output instead of the text a person reads. For recall this matters: the output carries matched and a script must check it before acting on the results, because a miss returns nothing rather than the whole scope.

Flags take one dash or two (-n 5 and --n 5 are the same) and may come before or after the positional words, so recall foo --json works. The tables below list every flag each command registers, taken from os-brain help <command>. Positional arguments (a subcommand, an id, a query) follow the command name.

Writing #

Three commands put things into the brain. Each one is a single line on purpose: when saving a fact takes effort, nobody saves it.

remember store a memory (same scope+title updates in place)

Saves a fact that should last. A memory is identified by its scope plus its title (normalised for case, punctuation and accents), so saving the same title again in the same scope improves that memory instead of adding a copy. Words typed straight after remember are the title.

Three refusals protect the store. A different body under an existing title is refused unless you say what you mean: --update replaces it (the old version goes to history), --supersedes records that the fact changed. A second memory about the same subject in the same scope is refused with the id already held. And --confidence confirmed is refused unless someone outside this session could check it, because confirmed outranks everything else for good and so takes evidence rather than a self-assessment.

$ os-brain remember "nginx terminates TLS on the edge box" --type infra \
      --body "The edge box runs nginx; the app servers only speak plain HTTP on loopback."
remembered #1 [global/infra] nginx terminates TLS on the edge box

$ os-brain remember "Invoice rounding happens in the ledger" --type decision \
      --body "Rounding moved from the API to the ledger so totals match the PDF." --confidence confirmed
refusing 'confirmed': nothing here can be checked by anyone who was not in this session.
  'confirmed' outranks everything else forever, so it takes evidence, not a self-assessment.
  Add --source "<file, command or URL>", --ref "<path:line>", or --source "stated by the user" (the phrase itself, not a source that contains the word); or store it as --confidence reported.

prefer store how the user wants to be worked with

Records how the user wants to be worked with. It is one short command because a preference that takes effort to save never gets saved. --why is the part that matters three months later, when the rule looks arbitrary and nobody remembers what caused it. The prompt hook spots preference language in what the user types and reminds the agent to save it.

$ os-brain prefer "answers first, reasoning after" --why "asked twice"
remembered #5 [global/preference] answers first, reasoning after

Adds an entry to the activity log. Log entries are never ranked and never fade. They answer "what did the last session actually do" and the brief reads them for exactly that. Declare kinds with os-brain kind add so map can tell a real kind from a typo.

logged event #1 [deploy] deployed 1.4 to staging

Reading #

What a session reads. brief and wakeup are the handoff, recall is the search and the rest answer narrower questions.

recall retrieve ranked memories

Full-text search first, then the ranking score (relevance, type, confidence, age and use). A superseded memory does not vanish: recall follows the link to its replacement and returns that, so a search in the old wording still finds the current fact. When no memory holds most of the words in the query, the answer is labelled a loose match: leads, not answers.

A miss returns nothing. With --json, when nothing matches you get an empty result, not the whole scope. The output carries matched so a script can tell the two apart. It works this way because a script once fed a recall miss into a forget loop and deleted real memories: the warning was in the text output and the script was reading JSON.

An unknown --type or --tier is an error, never an empty result, so a typo cannot pass for "nothing stored".

$ os-brain recall "invoice rounding"
#2  [global/decision] (score 0.483) Invoice rounding happens in the ledger [confirmed]
      Rounding moved from the API to the ledger so totals match the PDF.
      (stated by the user)

$ os-brain recall "kubernetes ingress" --json
{
  "count": 0,
  "matched": false,
  "query": "kubernetes ingress",
  "results": [],
  ...
}

wakeup session open: the brief, the working tree and this project's own probes

What the session-start hook runs: the brief, plus the live state of the working tree read from git (staged, modified and untracked files by name, unpushed commits, a merge or rebase left half done), plus any probes this project declared. It goes straight into a session, so it is trimmed to 6000 bytes by default.

A probe is a shell command the project wants run when a session opens, declared with wakeup add --name --run and managed with rm and list. Probes live in brain.json, which is committed, so a probe list arrives with every clone. That is why a probe only runs after wakeup trust, which a person answers at a terminal after seeing the exact text. It is refused over MCP. Editing a probe revokes its approval. Over HTTP, add and rm are refused too: a remote caller does not get to edit what this machine runs.

$ os-brain wakeup add --name tests --run "go test ./... 2>&1 | tail -3"
$ os-brain wakeup trust          # a person, at a terminal, types yes
$ os-brain wakeup --no-probes    # the brief and the tree, nothing run
FlagWhat it does
--chars <n>Probe output kept. Default 1200, max 8000.
--emit <text>Print the envelope a host agent needs instead of plain text: cursor, gemini, codex or hermes. init sets this for you. Without it, plain text.
--max-bytes <n>Trim from the least important end to fit; 0 for all of it. OS_BRAIN_MAX_BYTES sets the default.
--name <text>Probe name, for add and rm.

--no-cursorDo not move the last-brief marker.

Correcting #

A fact that was wrong, or stopped being true, is corrected in place rather than deleted. The old version stays in history so a mistake can always be traced.

update edit a memory

For the same fact in better words. It takes most of what remember takes. --trust, --valid-from, --valid-to, --supersedes and --allow-duplicate are set when a memory is first written and cannot be changed later. When the fact itself changed, use remember --supersedes instead, so a search in the old wording lands on the new fact.

$ os-brain update 2 --body ""
refusing to blank the body of #2 ('Invoice rounding happens in the ledger'), which holds 74 characters.
An empty --body is usually a command that failed to produce the text it meant to pass.
If you do mean to empty it, pass --force. To retire the fact instead, forget it or supersede it with the memory that replaces it

Tasks and measures #

Neither one is a memory and we keep them apart on purpose: a task is something owed by a date and a measure is a number that only means something as a series. Tasks has its own page.

task what is owed, by whom and when: reminders, recurrence, an ordered list

What is owed, by whom and when. With no subcommand it lists the open tasks. The subcommands are add, list, due, done, drop, wait, reopen, snooze, set and todo. A flag the subcommand does not read is refused rather than ignored. A task is delivered when a session is open and somebody is typing: nothing here wakes a machine or acts unattended.

$ os-brain task add "renew the edge certificate" --when "every monday 9am"
task #1 [user] renew the edge certificate
  due 2026-11-23 09:00 (every mon at 09:00)

$ os-brain task list
[ ] #1   renew the edge certificate  (due 2026-11-23 09:00 · every mon at 09:00)

$ os-brain task snooze 1 --until "in 2 hours"
$ os-brain task done 1
$ os-brain task todo --out TODO.md

--allow-trackedWith todo: write to a git-tracked path.

Keeping it healthy #

An old fact looks exactly like a current one. That is the biggest risk with any memory and these four commands are how you catch it.

review hygiene report: duplicates, decay, promotions

The hygiene report: duplicates, memories past their decay, memories worth promoting and tier A or B facts nobody has re-checked in --stale-days. The duplicate scan compares memories in pairs, so it is capped. It finishes with what this brain has never used at all, such as no event logged or no summary in the shared index.

$ os-brain review --stale-days 90
FlagWhat it does
--duplicatesRun the pairwise scan anyway.
--max-pairwise <n>Skip the pairwise duplicate scan when it would compare more memories than this. Default 600.
--n <n>How many items per section. Default 8.
--stale-days <n>Tier A/B unverified for this long is flagged. Default 180.

doctor check the brain for inconsistency

Checks the brain for inconsistency: dangling links, supersede cycles, index drift and series that mix units. --fix repairs what can be repaired and names the rest.

no problems found
FlagWhat it does
--fixRepair the repairable problems.

Rebuilds the full-text index from the memories table, when doctor reports drift.

$ os-brain reindex

No flags of its own. It prints plain text even with --json.

vacuum checkpoint the WAL and compact the database

Checkpoints the write-ahead log and compacts the database file.

$ os-brain vacuum

No flags of its own beyond --json.

Deleting #

Agents drive the brain and an agent that typed a delete is not asked whether it is sure. If you typed it, you meant it. A guard flag is still needed in a few cases and each one catches an accident rather than a decision:

  • update --body "" on a body that has text needs --force. A failed shell substitution produces an empty string that once wiped a runbook while reporting success.
  • forget of a pinned memory, a guardrail or the current version of a correction needs --force. A wrong id would hit exactly what the brief opens with.
  • restore over a memory that is still current needs --force.
  • import of a dump that brings guardrails, or retracts a pinned memory or a guardrail, needs --force. A dump is a file somebody handed you; the dry run lists what it would do.
  • The big deletions (forget --all, pruning tier A or B, anything across --all-projects) need --i-mean-it.

What they have in common: when the tool cannot tell what you meant, it does nothing and says so. It never does the biggest thing it could.

forget delete a memory (leaves a tombstone)

Deletes one memory and leaves a tombstone so the same fact is not learned again as new. It archives first (so restore can undo it) and records --reason. Without --force it refuses a pinned memory, a guardrail and a memory that supersedes others, because deleting that last one would put the facts it retracted back into search results.

--purge is for something that should never have been saved: no version is kept, every version already stored is deleted and nothing can bring it back. Typing it is the decision, so it includes --force. The tombstone stays, title only.

forget --all empties this project, pinned memories included. It is a dry run unless you add --apply and then --i-mean-it on top. It writes a dump of this project first. In a shared store it deletes this project's rows and nobody else's.

$ os-brain forget 1
#1 is pinned: 'nginx terminates TLS on the edge box'
Load-bearing memories are not deleted by accident. Re-read it (os-brain get 1), then use --force, or supersede it instead.

$ os-brain forget 4
#4 is the current version of 1 superseded memory. Deleting it would put these back into recall as live facts:
  #3 Rounding of invoices is done by the ledger
Supersede it with a correct version instead, or pass --force to accept the resurrection.

$ os-brain forget --all
...
would delete:
  memories         4
...
4 rows. Nothing has been changed. Add --apply --i-mean-it to do it.

Export, import, backup and snapshot #

Export carries everything, so you are never locked in. A snapshot is generated, never written by hand: keep a hand-written memory file next to a brain and sooner or later the two disagree without telling you.

Every command that writes a file follows the same rules. That means export --out, snapshot --out, backup --out, task todo --out and the dumps that prune, forget --all and uninstall take before deleting. They refuse to overwrite a file that lacks their own generated-by marker, refuse a path inside a git repository that is not gitignored, refuse a path outside the project, refuse to write through a symbolic link and write with mode 600. --force, --allow-tracked and --allow-outside each lift exactly one of those. Nothing lifts the symbolic link rule, because a link committed in a repository can point at any file you own.

$ os-brain export --out dumps/e.json
dumps/e.json is inside a git repository and is not gitignored.
A snapshot is every memory in cleartext.
  gitignore it, then re-run   no flag needed, and the usual answer
  a path outside the project  needs --allow-outside
  commit it deliberately      needs --allow-tracked

export dump the whole brain as JSON (take one before pruning)

The whole brain as JSON: memories with their provenance and links, events, leads, tasks and measures. Take one before pruning. Without --out it prints to stdout.

$ os-brain export --out dumps/orchard.json
exported 4 memories, 2 events, 0 leads to dumps/orchard.json

Across projects #

These live in the shared store that every project on the machine reads. Nothing that arrives through them has any authority. A note is information. Only the person at the keyboard gives orders.

Changing one is refused over MCP, refused from a process running under an agent's session and, at a terminal, shows the change and waits for "yes". Nearly every command as an MCP tool, over stdio or Streamable HTTP with --http <addr>. Off loopback it refuses to start without --tls-cert, --tls-key and --token. On loopback with no token it mints one into a mode-600 file. --public-url mounts OAuth for hosted clients. The MCP page covers it.

Install and lifecycle #

How a brain is created, seeded and removed again.

init create a brain in this project and wire the session hooks

Creates a brain in this project and wires the agent hooks. It writes brain/brain.json (meant to be committed), brain/brain.db (added to .gitignore), brain/HOWTO.md, brain/BEST-PRACTICES.md and brain/autoexec.sh (the script most agents call from their hooks). For Claude Code it also adds slash commands under .claude/commands/. At a terminal it asks which agent to wire; with no terminal it wires every agent whose config directory it finds in the project or your home directory. When an agent cannot be wired it prints the block to add by hand rather than pretending. It never writes into CLAUDE.md. Running it again is safe: it brings the database up to the current schema in place and never overwrites it. The agents page shows what it writes for each agent.

It refuses a project where a file it would write is a symbolic link or sits under one. It checks before writing anything: a cloned repository could commit a link at .claude/settings.json that points at a file in your home directory.

$ os-brain init --agent claude
brain ready at /home/you/src/orchard/brain/brain.db
  + brain.json for 'orchard'
  + brain.db at schema v16
  + .gitignore entry for brain/brain.db*
  + HOWTO.md
  + BEST-PRACTICES.md
  + SessionStart hook -> OS_BRAIN_HOME="$CLAUDE_PROJECT_DIR/brain" os-brain wakeup
  + Stop hook -> OS_BRAIN_HOME="$CLAUDE_PROJECT_DIR/brain" os-brain hook-stop
  ...

--no-gitignoreDo not add brain.db to .gitignore.
